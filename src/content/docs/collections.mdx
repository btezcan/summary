## Summary

- C# has fixed-size **arrays** (`int[]`) and growable **lists** (`List<T>`).
  Python's built-in **`list`** grows as needed and plays both roles.
- **Dictionaries** map keys to values: `Dictionary<TKey, TValue>` ↔ `dict`.
  Python keeps insertion order (guaranteed); C# does **not** promise any order.
- **Sets** hold unique items (`HashSet<T>` ↔ `set`); **queues** and **stacks**
  are `Queue<T>` / `Stack<T>` ↔ `collections.deque` / `list`.
- Removing items from a list **while looping over it** throws in C# but
  **silently skips items** in Python. Build a new list instead.
- Choose by the question you ask most often: "item at position *i*?" → list;
  "value for key *k*?" → dictionary; "have I seen *x*?" → set.

## Concept

### Arrays and lists

A C# **array** has a fixed length, set when it is created; its elements start
at their default value (`0`, `false`, `null`). A **`List<T>`** grows as you add
items. Python has no fixed-size array in the core language: its `list` grows,
shrinks and can hold values of any type (though a list of one type is the
norm).

<Pair id="collections/arrays">
  Both index from `0`, and both can count from the end: `names[^1]` (C#) and
  `names[-1]` (Python). Arrays have `Length`; lists have `Count` in C# and
  `len()` in Python.
</Pair>

<Pair id="collections/list-basics">
  `Add` / `append`, `Remove` / `remove` and `Sort` / `sort` map one to one.
  Python prints a list directly; C# needs `string.Join` for readable output.
</Pair>

<Pair id="collections/list-more">
  Python's `del names[0]` removes by position, like `RemoveAt`. A **slice**
  `names[0:2]` copies part of a list; C#'s `GetRange(0, 2)` does the same (and
  arrays support ranges, `array[0..2]`).
</Pair>

### Sorting

`list.sort()` / `List.Sort()` sort **in place** and return nothing. Python's
`sorted(...)` and C#'s LINQ `OrderBy(...)` return a **new** sorted sequence and
leave the original alone.

<Pair id="collections/sorting">
  Python sorts by a **key** (`key=len`); C#'s `Sort` takes a **comparison**
  (`(a, b) => …`). Python's sort is **stable**: items that compare equal keep
  their order (`kiwi` before `pear`). `List.Sort` does not promise that; LINQ's
  `OrderBy` does.
</Pair>

### Dictionaries

A dictionary stores **key → value** pairs and finds a value by its key in about
constant time, however many entries there are.

<Pair id="collections/dictionary">
  `TryGetValue` and `get` both avoid an error for a missing key. Both loops
  happen to print in insertion order here, but only Python **guarantees** it; a
  C# `Dictionary` can reorder entries after removals, so don't rely on its order.
</Pair>

### Two dimensions

C# has true **rectangular arrays** (`int[,]`) and **jagged arrays**
(`int[][]`, an array of arrays whose rows may differ in length). Python uses a
list of lists, which is jagged by nature.

<Pair id="collections/matrix">
  `grid[1, 2]` (C#, one index pair) versus `grid[1][2]` (row, then item). For
  serious numeric work in Python, the `numpy` library provides real
  multi-dimensional arrays.
</Pair>

### Sets, queues and stacks

<Pair id="collections/set-queue-stack">
  `HashSet.Add` returns `false` for a duplicate; Python's `set.add` returns
  nothing and simply ignores it. Use `deque` for a queue in Python:
  `list.pop(0)` works but gets slow for long lists, because every remaining
  item moves.
</Pair>

Python's set operators make set algebra short:

<Pair id="collections/set-operations">
  Both print sorted results on purpose: a set has no order, and Python's
  iteration order can even change between runs. C# needs a new set per
  operation (or LINQ's `Intersect` / `Union`), which is why the C# side is longer.
</Pair>

### Collection literals

<Pair id="collections/collection-expressions">
  C#'s **collection expressions** `[1, 2, 3]` and the **spread** `..` look like
  Python's list literals and `*` unpacking.
</Pair>

<Note type="version" version="C# 12">
  Collection expressions are new in C# 12. Older code writes
  `new[] { 1, 2, 3 }` or `new List<int> { 4, 5 }`, as in the other examples.
</Note>

### Tuples

<Pair id="collections/tuples">
  A tuple groups a few values without defining a type. C# tuples can name their
  elements (`best.Name`); Python tuples are indexed (`best[0]`) and
  **immutable**. For anything with more than two or three fields, use a record
  or dataclass (chapter 9).
</Pair>

O(n) means the time grows with the number of items. Checking `x in items` for a
list of a million names looks at up to a million entries; in a set, it's one
hash lookup.

## Common Mistakes

<Mistake lang="cs" title="Changing a list inside foreach" wrong="collections/m-modify-foreach" right="collections/m-modify-foreach-fixed">
  A `foreach` loop may not add or remove items. Use `RemoveAll`, loop backwards
  with an index, or build a new list.
</Mistake>

<Mistake lang="py" title="Removing items while looping" wrong="collections/m-remove-while-iterating" right="collections/m-remove-while-iterating-fixed">
  Python doesn't stop you. Removing an item shifts the rest left, so the loop
  skips the element right after it — here, the second `2`. The C# version of this
  code at least throws; this one produces a wrong answer quietly.
</Mistake>

<Mistake lang="cs" title="Reading a missing key" wrong="collections/m-missing-key" right="collections/m-missing-key-fixed">
  The indexer throws `KeyNotFoundException`; Python's `d["Zeynep"]` raises
  `KeyError`. Use `TryGetValue` / `get` when a key may be missing.
</Mistake>

<Mistake lang="cs" title="Length on a List" wrong="collections/m-length-count" right="collections/m-length-count-fixed">
  Arrays have `Length`, collections have `Count`. Python has one answer for
  everything: `len(x)`.
</Mistake>

<Mistake lang="py" title="Multiplying a list of lists" wrong="collections/m-grid-alias" right="collections/m-grid-alias-fixed">
  `[[0] * 3] * 2` repeats a reference to the **same** row. Build each row
  separately with a comprehension.
</Mistake>

<Mistake lang="py" title="Keeping the result of sort()" wrong="collections/m-sort-none" right="collections/m-sort-none-fixed">
  `sort()` sorts in place and returns `None`. Use `sorted()` for a new list. In C#
  the equivalent line doesn't compile, because `Sort()` returns `void`.
</Mistake>

## Predict the Output

<Predict id="collections/p-copy">
  `b = a` copies the reference: one list, two names. `new List<int>(a)` and
  `list(a)` create an independent copy, so `c` still has two items.
</Predict>

<Predict id="collections/p-remove-missing">
  `List.Remove` reports failure by returning `false`. Python's `remove` raises
  `ValueError`; check with `in` first, or catch the error.
</Predict>

<Predict id="collections/p-set-bool" lang="py">
  A set keeps one of each **equal** value, and in Python `1 == 1.0 == True`. So
  the set holds `1` and `2`: length 2.
</Predict>

## Working with AI

Good prompts for learning this topic:

- "I need to store students and look them up by number, then list them sorted by
  name. Which C# and Python collections should I use and why? Don't write the
  program."
- "Show me three ways to remove items from a list while looping, in C# and in
  Python. Which ones are wrong, and how does each language react?"

<Note type="warning" title="Verify it yourself">
  AI code sometimes relies on dictionary order in C#, or prints a Python `set`
  and expects a fixed order. Run such code twice, change the input order, and
  check that the output still makes sense.
</Note>
