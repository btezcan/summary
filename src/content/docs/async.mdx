## Summary

- `async` / `await` let a program **wait for I/O** — network, disk, timers —
  without blocking. While one operation waits, others can make progress.
- C#: an `async` method returns a `Task` or `Task<T>`. Python: an `async def`
  function returns a **coroutine**; `asyncio.run(main())` starts the event loop.
- Run independent operations **concurrently** with `Task.WhenAll` /
  `asyncio.gather`: two 0.3-second waits take about 0.3 seconds, not 0.6.
- A C# `Task` **starts immediately** when created. A Python coroutine does
  **nothing until it is awaited** (or wrapped in a task).
- Never block inside async code: no `.Result` / `.Wait()` in C#, no
  `time.sleep()` in Python. Always `await`.

## Concept

### Why asynchronous code

Most waiting in programs isn't computing — it's waiting for a server to answer or
a disk to deliver data. **Synchronous** code sits idle during that time.
**Asynchronous** code says "continue here when the result is ready" and lets the
program do other work meanwhile. It's about **waiting efficiently**, not about
computing faster.

### The basic shape

<Pair id="async/basics">
  `await` pauses the method until the result is ready, then continues on the next
  line; to the reader, the code still looks sequential. C# allows `await` directly
  in top-level statements. Python needs an `async def main()` started with
  `asyncio.run(...)`. `Task.Delay` and `asyncio.sleep` stand in for real I/O
  here.
</Pair>

### Tasks start immediately; coroutines wait

This is the biggest difference between the two models, and the source of real
bugs when translating code. Calling an `async` method in C# **starts** it: it runs
until its first `await`. Calling an `async def` function in Python only
**creates** a coroutine object; nothing runs until it is awaited or wrapped with
`asyncio.create_task(...)`. The first Predict exercise below shows the effect.

## Examples

### Waiting for several things at once

<Pair id="async/concurrent">
  Awaiting one download after the other takes the sum of the waits. Starting both
  and awaiting them together with `WhenAll` / `gather` takes about as long as the
  slowest one. (The samples print comparisons instead of exact times, because
  times vary from run to run.)
</Pair>

<Note type="tip" title="Python 3.11: TaskGroup">
  `asyncio.TaskGroup` (`async with asyncio.TaskGroup() as tg: tg.create_task(…)`)
  is a newer, safer alternative to `gather`: if one task fails, the others are
  cancelled.
</Note>

## Common Mistakes

<Mistake lang="cs" title="Forgetting await" wrong="async/m-no-await" right="async/m-no-await-fixed">
  The task was started but nobody waited for it, so the program ended before
  `saved` could print. The compiler warned (CS4014). Worse, any exception inside
  the task is lost.
</Mistake>

<Mistake lang="cs" title="async void" wrong="async/m-async-void" right="async/m-async-void-fixed">
  An `async void` method can't be awaited, so the `try` / `catch` around the call
  finishes before the exception happens — and the exception then crashes the
  whole process. Use `async Task`. `async void` exists only for event handlers.
</Mistake>

<Mistake lang="py" title="Forgetting await" wrong="async/m-no-await" right="async/m-no-await-fixed">
  `save()` only created a coroutine, which was never run: Python warns "coroutine
  'save' was never awaited", and mypy reports the unused coroutine. Unlike C#,
  none of `save` ran at all.
</Mistake>

<Mistake lang="py" title="Blocking sleep inside async code" wrong="async/m-blocking-sleep" right="async/m-blocking-sleep-fixed">
  `time.sleep` blocks the only thread, so the event loop can't switch to the
  other download — they run one after the other. The C# equivalent is calling
  `.Result`, `.Wait()` or `Thread.Sleep` inside async code.
</Mistake>

## Working with AI

Good prompts for learning this topic:

- "Explain the difference between concurrency and parallelism with a restaurant
  analogy, then show where async/await fits, in C# and Python."
- "Here is my async code. Point out every place where it blocks or forgets to
  await, but don't rewrite it."

<Note type="warning" title="Verify it yourself">
  When AI translates async C# to Python, it often forgets that Python coroutines
  don't start by themselves, or leaves `time.sleep` / `.Result` in async code. Add
  timing checks like the ones on this page: if concurrent code takes as long as
  sequential code, something is blocking.
</Note>
